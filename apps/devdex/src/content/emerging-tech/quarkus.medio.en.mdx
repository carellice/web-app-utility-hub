# Quarkus — Compared to Spring

## Quick comparison

| Aspect | Spring Boot | Quarkus |
|---|---|---|
| Philosophy | Runtime conventions | Build-time conventions |
| Dev loop | Manual restart (even with Devtools) | Instant live reload |
| Native | Possible with AOT since Spring 6 | Native "in-house" since v1 |
| Reactive | WebFlux (Reactor) | Mutiny + Vert.x |
| Extensions | Maven starters | Extensions with metadata |
| Standards | Spring-specific | Jakarta EE + MicroProfile |

## Programming models

Quarkus supports both:

- **Imperative** (servlet/blocking) with virtual threads (`@RunOnVirtualThread`).
- **Reactive** with Mutiny (`Uni<T>`, `Multi<T>`).

```java
@GET
public Uni<List<Fruit>> all() {
    return Fruit.listAll();   // panache + mutiny
}
```

## Panache: simplified persistence

Extends JPA/Hibernate with an "Active Record"-style API:

```java
@Entity
public class Fruit extends PanacheEntity {
    public String name;
    public String color;
}

// usage
List<Fruit> red = Fruit.list("color", "red");
Fruit.deleteById(42L);
```

## Configuration

Uses `application.properties` like Spring, but can be overridden at runtime via env
vars following MicroProfile Config:

```
quarkus.datasource.username=devdex
QUARKUS_DATASOURCE_PASSWORD=secret
```

## Tests

`@QuarkusTest` boots the context in-process. It is very fast because Quarkus does
not scan anything at runtime.

```java
@QuarkusTest
class HelloTest {
    @Test void ok() {
        given().get("/hello").then().statusCode(200);
    }
}
```
